# v0.3.1 Engineering Hardening — Acceptance Matrix

**Target branch:** feature/research-figure-making-v0.3.1-hardening  
**Base:** v0.3.0a1 foundation commit  
**Release intent:** Correctness and contract stabilization; no CLIP, ELK or PPTX feature expansion.

## Acceptance principles

A passing test count is not sufficient by itself. Each scientific or engineering contract must have a negative test that proves invalid input is rejected, plus a positive test that proves valid input remains supported.

| Work package | Acceptance condition | Evidence |
|---|---|---|
| E0.1 Atlas integrity | Paper/figure foreign keys are unique and valid; taxonomy is loaded and every controlled facet is a member of the declared vocabulary; year filters are inclusive and reject invalid ranges; SearchHit exposes the figure locator and metadata provenance; benchmark queries resolve relative to the selected Atlas directory. | tests/test_v031_hardening.py Atlas, taxonomy, locator and year-filter tests; package CLI test |
| E0.2 Scientific contracts | Every content block is assigned to a panel; a Brief-bound Scene must carry the matching brief_id; every scientific node has a matching content-block role and panel; required graph paths preserve edge type; target dimensions, layout and minimum font constraints are enforced; optional Atlas validation rejects unknown figure IDs. | Brief coverage, role, constraint and typed-path tests; render CLI integration |
| E0.3 Schema/runtime consistency | Both schemas pass Draft 2020-12 meta-schema validation; examples validate against their schemas; runtime validators apply the same structural contracts; unknown properties and invalid enumerations are rejected; renderer capability checks fail before export. | JSON Schema tests and runtime negative tests |
| E0.4 Rendering fidelity | Point-to-pixel conversion uses 96/72; subtitles and semantic metadata survive draw.io export; SVG and draw.io use the same declared route class; orthogonal routes are rendered; self-loops and unsupported spline/layered layouts fail explicitly. | SVG/draw.io tests, capability tests and XML assertions |
| E0.5 Provenance and QA | Manifest records all declared source and output hashes, package version, transformations, Brief/Scene IDs, reference bindings and QA results; SVG font units are normalized; geometry QA reports axis-aligned node overlaps. | Manifest hash, SVG unit and geometry tests; render CLI artifact |
| E0.6 Package distribution | Wheel includes Atlas data and JSON Schemas; default Atlas and query paths resolve after installation from an unrelated working directory; clean wheel installation can run both reference CLIs. | CI wheel-build and external-working-directory step |
| E0.7 CI regression | Python 3.10 and 3.12 run static checks, schema checks, unit/integration tests, synthetic figures, scene exports and existing publication regression suites. | GitHub Actions matrix |

## Explicit capability boundaries

The v0.3.1 hardening release does not claim to implement:

- CLIP image embeddings or image-to-image retrieval.
- Automatic PDF figure extraction or caption-to-figure matching.
- ELK layered auto-layout.
- Spline routing or self-loop geometry.
- Full text-glyph measurement, collision detection or edge-crossing optimization.
- Native PPTX export or draw.io-to-Scene round-trip import.
- Human-rated publication-quality certification.

The SVG geometry audit is an axis-aligned node-box overlap check. The SVG text audit reads declared font sizes and cannot prove final rendered glyph bounds. These limitations must remain visible in QA output and release notes.

## Release gate

The branch is ready for a v0.3.1 release candidate only when:

1. The complete GitHub Actions matrix is green.
2. The clean wheel-install step succeeds from outside the repository.
3. The generated SVG, draw.io XML and manifest are inspected as artifacts.
4. The acceptance matrix has no unverified row.
5. No source files on main or the original v0.3 branch were modified.

A green CI run proves the implemented contracts and regression fixtures pass. It does not certify arbitrary user-generated scientific figures as scientifically correct or publication-ready.
