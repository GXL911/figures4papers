# Research Figure Making v0.3 — Architecture and Engineering Decisions

**Status:** foundation implementation  
**Branch:** feature/research-figure-making-v0.3  
**Baseline:** feature/research-figure-making-v0.2  
**Package version:** 0.3.0a1

## 1. Product objective

Move from a collection of publication-oriented plotting utilities to a reference-grounded scientific figure design system.

The system must preserve scientific semantics and evidence while using external paper figures as design references. It must not reproduce third-party artwork by default, and it must not delegate final geometry or data rendering to an unconstrained image-generation model.

The intended pipeline is:

Research Context → Reference Retrieval → Design Brief → Scene Graph → Deterministic Rendering → Scientific and Visual QA → Editable Deliverables.

## 2. Architecture layers

### Layer 1 — Scientific Understanding

Inputs include the research question, intended claim, methods, data, experimental units, uncertainty conventions, limitations and target publication constraints.

The output is a Scientific Figure Design Brief. It records the question and takeaway, the figure's narrative role, content blocks and scientific roles, a panel-by-panel claim and visual-form plan, reference figures and why each is relevant, physical-size and output constraints, and known limitations.

A design brief is not yet a drawing. It states what the figure must communicate.

### Layer 2 — Reference Intelligence

The atlas is metadata-first. Paper metadata and figure metadata are separate JSONL records connected by stable IDs.

A Paper record contains canonical identifiers, title, authors, year, venue, paper URL, abstract and metadata provenance.

A Figure record contains a paper foreign key, figure locator, paraphrased caption, summary, taxonomy facets, panel count, metadata provenance, curation status and rights status.

The first seed contains 16 papers and 16 figure records. All are marked provisional pending original-PDF visual verification. No paper-image binaries are stored.

Retrieval is composed of fielded BM25, hard filters, soft structural ranking, an optional semantic-score input from a future image/text embedding adapter, and Reciprocal Rank Fusion (RRF) over ranked lists.

Raw BM25 and cosine-similarity scores are not added directly because their scales are not calibrated. RRF combines ranks. Initial field boosts and equal source weights are baselines to be evaluated, not learned or proven optimal parameters.

The first implementation intentionally does not install CLIP, PyTorch or model weights. A semantic provider can later supply a mapping from figure IDs to finite similarity scores. This keeps the core package lightweight and makes the lexical/structural baseline reproducible.

### Layer 3 — Figure Design Intelligence

The Design Brief is converted into a renderer-neutral Scene Graph.

The taxonomy is orthogonal:
- scientific intent: what question or explanation is required;
- figure role: what the figure contributes to the paper narrative;
- visual form: what kind of visual object is used;
- layout pattern: how elements are spatially arranged;
- evidence type: what kind of evidence is displayed.

These labels must not be collapsed into a single mutually exclusive class. A reliability diagram can be a calibration diagnostic, quantitative evidence, and a single-panel curve at the same time.

The Scene Graph preserves stable node and edge IDs, labels and scientific roles, directed source/target relationships, geometry in millimetres when manually laid out, and style tokens independent of rendering backend.

Scene nodes can bind back to Design Brief content-block IDs, panel IDs and scientific roles. A cross-contract validator checks that each panel's planned content blocks are represented in the scene before rendering, and that required scientific relations (data/control flow, skip, attention or feedback) survive into the scene graph. The scene is the editable source of truth. Rendered SVG or PNG is an output, not the canonical data model.

### Layer 4 — Rendering

The existing v0.2 renderers remain: Matplotlib for data-bearing statistical plots; DiagramCanvas for vector mechanism diagrams; FigureComposer for multi-panel composition.

The v0.3 foundation adds a deterministic adapter from a manually positioned Scene Graph to DiagramCanvas SVG and a native draw.io mxCell XML exporter.

Automatic layered layout is not yet implemented. ELK is the preferred candidate because it separates layout computation from rendering and supports layered graphs, ports, edge routing and compound graphs. The interface should be integrated without coupling the semantic Scene Graph to ELK-specific data structures.

PPTX native-shape export is a later adapter. It should map Scene Graph objects to PowerPoint shapes, text boxes and connectors rather than inserting one flattened screenshot.

### Layer 5 — Scientific and Visual QA

QA is multi-dimensional and must report separate findings.

**Scientific:** source values and transformations; units and estimands; experimental unit and independence assumptions; uncertainty convention; claim-to-panel traceability; no unsupported scientific inference.

**Structural:** unique stable IDs; every edge endpoint exists; no duplicate or dangling elements; graph connectivity and expected relationships; no missing required content blocks.

**Geometric:** all nodes within canvas bounds; no unintended overlaps; edge crossings and routing quality; panel alignment and whitespace.

**Typographic and visual:** final physical-size font checks; contrast and redundant encodings; text overflow and clipping; grayscale and color-vision review; manual review at the target journal width.

DiagramEval motivates an additional graph-aware evaluation layer: Node Precision/Recall/F1 for scientific content elements and Path Precision/Recall/F1 for directed relationships. The current cross-contract validator enforces exact content-block and required-relation preservation; it is not yet a full fuzzy DiagramEval implementation or a visual-quality metric.

Existing SVG QA checks basic structure, title, role, viewBox, duplicate IDs and declared font sizes. It does not yet solve general text measurement, collision detection, edge-crossing optimization or publication-level human review.

## 3. Reference data model and curation policy

Use arXiv IDs, DOI or OpenReview identifiers as canonical paper IDs when available. A figure ID is stable within the atlas and must never depend on its current display order.

Every paper and figure record has a source URL. Future ingestion should record provider, retrieval timestamp, provider record ID and field-level provenance where possible.

OpenAlex and Crossref are suitable discovery/metadata sources; OpenReview is useful for review-managed venues. OpenReview currently supports API 2 while some older conferences still require API 1. API responses must be normalized into our internal schema rather than stored as the product schema.

Default rights policy is reference-only: store bibliographic metadata and a figure locator; paraphrase captions and record design observations; link to the paper or publisher source; do not mirror the figure image; do not assume an open paper URL means the image can be redistributed.

A local image asset is rejected unless its rights status is open-license or permission-confirmed and a license is recorded. Rights must be checked per asset, not inferred from the repository's code license.

Curation states:
- provisional: locator and design description need original-PDF visual verification;
- machine_extracted: extracted automatically and not yet human verified;
- curated: a human has checked the exact figure, caption, panel boundaries and source.

The initial 16 records are provisional, not a completed 30–50-image gold set.

## 4. Taxonomy

| Facet | Question | Example |
|---|---|---|
| Scientific intent | What should the reader understand? | explain_mechanism |
| Figure role | What job does the figure do in the paper? | architecture_overview |
| Visual form | What visual object is drawn? | block_diagram |
| Layout pattern | How are elements arranged? | branched_pipeline |
| Evidence type | What evidence is represented? | calibration |

The taxonomy is a controlled vocabulary, not a trained classifier. New values should be added through a reviewed taxonomy change with a definition and positive/negative examples.

## 5. Retrieval algorithm

Fielded BM25 uses separate term frequencies, document lengths and average field lengths per field. Initial parameters are k1=1.2 and b=0.75. Initial field boosts are title 3.0, caption 2.4, keywords 2.2, summary 1.8, abstract 1.3, role 1.2, visual form 1.1, layout 0.9 and venue 0.3. These values are starting hypotheses; tune them only on a judged development set.

Hard filters define eligibility. Soft facets contribute an independent ranking. This distinction avoids turning every user preference into a hard exclusion.

A future CLIP adapter may embed query text and reference images. CLIP is a broad image-text representation model, not a diagram-structure evaluator. A semantic score must therefore remain one signal among several. Figure text, caption text and explicit graph structure may be more useful than global image similarity alone.

For each source ranking, RRF adds 1/(k + rank), with k=60 initially. Default source weights are equal. Ranking contribution is retained in each SearchHit so the system can explain why a figure was retrieved.

A cross-encoder or vision-language reranker may be added only after we have judged query/reference pairs. It should rerank a bounded candidate pool, not replace the fast retrieval layer.

## 6. Retrieval evaluation

The repository includes eight hand-curated development queries and relevance grades. The evaluator reports MRR@k, Recall@k and nDCG@k.

These qrels are a smoke-test fixture, not a benchmark. They were authored alongside the seed metadata and have not been independently judged by multiple annotators.

Before claiming retrieval quality:
1. expand to 30–50 visually verified references;
2. create at least 30–50 queries across architecture, mechanism, pipeline, graph, calibration and statistical-result tasks;
3. obtain independent relevance judgments;
4. report inter-annotator agreement and adjudication;
5. compare BM25-only, facets-only, BM25+facets, CLIP-only, BM25+CLIP and full RRF;
6. report per-domain and per-figure-form results, not only a macro average.

## 7. Editable output contract

The internal Scene Graph is canonical. SVG is the first-class vector output; PDF/PNG use the current deterministic export path; draw.io is the v0.3 first editable adapter for manually laid-out boxes, circles and directed connectors; PPTX and ELK are future adapters.

A draw.io export is editable as mxCell vertices and edges. It is not yet a full-fidelity import/export round-trip system. Text styling, compound groups, complex connectors and arbitrary SVG paths remain outside the current subset.

## 8. Current implementation versus roadmap

Implemented in this foundation branch: metadata-first atlas schema and 16 provisional seed records; five-facet taxonomy; fielded BM25; hard filters and soft structural ranking; optional semantic score hook; RRF; eight-query qrels and retrieval metrics; Design Brief and Scene Graph JSON Schemas; runtime validators; deterministic manual SVG rendering; editable draw.io export for the supported scene subset.

Not implemented yet: automated PDF figure extraction and caption-to-figure matching; CLIP model loading, image embedding generation and vector index persistence; independently judged retrieval benchmark; LLM-driven scientific understanding and design-brief generation; ELK layered auto-layout and advanced edge routing; full overlap/collision/text-boundary QA; PPTX native-shape export; round-trip editing and import; human-rated publication-quality benchmark.

## 9. Next implementation sequence

1. Visually verify and expand the atlas from 16 provisional entries to 30–50 curated references.
2. Build a source-aware PDF ingestion tool with figure locator and rights audit.
3. Add a pluggable embedding provider and compare CLIP with lexical/structural baselines.
4. Add ELK layout through an adapter and evaluate node/edge preservation.
5. Build the Design Brief generation and review workflow.
6. Extend QA with graph consistency, collision, text bounds and final-size proof.
7. Add native PPTX export after the Scene Graph contract stabilizes.

Every new capability must have a testable contract and a measurable acceptance criterion.
